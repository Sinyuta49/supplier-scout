# Поставка — поиск и сравнение поставщиков

Рабочий прототип инструмента закупщика: найти компании по категории и региону, сравнить опубликованные условия и подготовить список для связи.

**Демо:** https://supplier-scout-artem.artem-goweb.chatgpt.site

**Зеркало интерфейса:** https://sinyuta49.github.io/supplier-scout/

Автор: Артём Синюта. Реализация выполнена с помощью AI-инструментов разработки.

## Проверить за две минуты

1. Нажмите «Упаковка для доставки»: увидите поставщиков упаковки в Екатеринбурге.
2. Отметьте FoodFace и U2B в сравнении. Откройте сравнение: минимальный заказ и порог бесплатной доставки показаны раздельно и с пояснениями.
3. Откройте «Данные и источники». Ссылки рядом с полями ведут к соответствующей странице поставщика.
4. Нажмите «Собрать свежие данные»: сервер заново прочитает открытую страницу. Ответ содержит время, источник, найденные контакты и фрагменты условий. При блокировке или тайм-ауте отображается явная ошибка, а не выдуманный результат.
5. Сохраните компанию, добавьте заметку. «Мой список» и заметки сохраняются после перезагрузки в этом браузере.
6. Скачайте CSV или скопируйте запрос коммерческого предложения. Сам сервис никому ничего не отправляет.

## Реализовано

- Поиск по товарным словам и названиям, 8 категорий, 3 основных региона, общая география.
- Примеры запросов и распознавание простых товарных/географических слов. Это детерминированный поиск, а не имитация LLM.
- 13 реальных компаний с официальными источниками, собранными 29.10.2026.
- Различение указанного региона работы и заявления о доставке по РФ.
- Фильтры прямого контакта и опубликованных сведений о документах.
- Сравнение до 4 компаний по одним и тем же критериям.
- Контакты, условия заказа, доставка, сведения о документах и ссылки на источники.
- Личный список, заметки, шаблон запроса условий, экспорт CSV с защитой от формул.
- Серверная повторная проверка публичной страницы, тайм-аут, ограничение объёма, ограниченные редиректы и кэш на 10 минут.
- Адаптивный интерфейс, клавиатурная навигация, пустые состояния и обработка сетевых ошибок.

## Что важно знать о данных

Это **ограниченный каталог и рабочий прототип**, а не полноценный поисковый индекс интернета. Если компании нет в выдаче, это не означает, что её нет на рынке. Новые поставщики автоматически не обнаруживаются.

Источники — официальные сайты поставщиков. Каждое заполненное условие имеет ссылку. Данные не являются офертой, проверкой надёжности бизнеса или гарантией наличия товара. «Есть сведения о документах» означает только заявление поставщика, не проверенные копии сертификатов. Бесплатная доставка от определённой суммы не считается минимальным заказом.

Если цена, партия или условия не найдены, интерфейс сообщает об этом. Отсутствие цены не интерпретируется как высокая цена. Невозможно корректно сравнить цены разных товаров без нормализации SKU, фасовки, НДС и условий поставки, поэтому прототип не придумывает числовую оценку «выгодности».

Повторный сбор извлекает контакты и текстовые фрагменты без LLM. Фрагмент может относиться к иному филиалу или контексту — он помечен как требующий проверки и **не заменяет** данные каталога. Кодировка старых сайтов и страницы с JavaScript/антибот-защитой могут требовать отдельного адаптера. Заметки и списки локальны: сервер их не получает, совместного доступа нет.

## Логика решения

```text
Категория + регион + товарный запрос
                 ↓
Отбор по каталогу и объяснимые ограничения
                 ↓
Карточки с фактами, пробелами и источниками
                 ↓
Сравнение → короткий список → запрос условий → CSV

«Собрать свежие данные»
        ↓
Worker → разрешённая страница → ограниченный fetch
        ↓
Контакты + фрагменты + URL + время / явная ошибка
```

По умолчанию первыми идут компании с указанным регионом работы, затем учитывается полнота опубликованных сведений. Это **не рейтинг надёжности**.

## Почему такой стек

- **HTML/CSS/JavaScript без UI-фреймворка:** быстрый запуск, простая проверка, нет сборки зависимостей и платы за клиентскую часть.
- **Cloudflare-compatible Worker:** сервер нужен для повторного чтения сайтов — прямой запрос из браузера обычно ограничен CORS. Публичный прототип не требует API-ключей или платных LLM.
- **GitHub Pages:** бесплатное зеркало интерфейса; обращается к тому же публичному Worker API.
- **Данные в модуле + localStorage:** достаточно для небольшого однопользовательского прототипа; упрощает повторяемую демонстрацию. Для общего рабочего сервиса нужна серверная БД.

LangChain и векторная БД здесь не добавлены: структурированный каталог из 13 компаний не требует семантического индекса, а прозрачность происхождения условий важнее генерации описаний.

## Запуск локально

Требуется Node.js 22+ (разработка и проверка: Node 24). Установка зависимостей не нужна.

```bash
npm run build
npm test
npm run validate
npm run dev
```

Откройте http://127.0.0.1:8931 . Для другого порта задайте `PORT`.

Для локального статического варианта можно раздавать `docs/` любым HTTP-сервером. Его функция сбора данных обращается к опубликованному Worker API; основная работа с каталогом остаётся клиентской.

## Структура

```text
src/catalog.mjs         Реальные компании, категории и происхождение полей
src/domain.mjs          Поиск, фильтры, сортировка, безопасный CSV
src/collector.mjs       Ограниченный сбор публичных данных
web/                    Интерфейс и клиентская логика
worker/handler.mjs      HTTP-маршруты и кэш
worker/index.js         Сгенерированный автономный Worker
scripts/build.mjs       Сборка Worker и зеркала GitHub Pages
scripts/dev.mjs         Локальный HTTP-сервер
tests/                  Проверки бизнес-логики, сборщика и HTTP
docs/                   Готовая статика для GitHub Pages
```

`worker/index.js` и `docs/` генерируются командой сборки. Менять нужно исходники в `src/`, `web/` и `worker/handler.mjs`.

## Проверки

14 автоматических тестов: категории и география, предметный запрос, пустая выдача, список, документы, безопасность CSV, происхождение данных, извлечение контактов, блокировка опасных редиректов, ошибки источника и HTTP-маршруты.

Дополнительно выполнен браузерный smoke-test: поиск, сравнение, карточки, заметки, сохранение после перезагрузки, пустое состояние, экранирование пользовательского ввода, отсутствие горизонтального переполнения на мобильном экране и ошибок JavaScript. Для воспроизведения на Windows с Chrome: запустите dev-сервер и `node scripts/browser-smoke.mjs`. Можно задать `CHROME_PATH` и `QA_URL`.

## Следующий шаг к промышленному сервису

1. Поисковый API с разрешённым коммерческим использованием для обнаружения новых компаний; очередь заданий и дедупликация по домену/ИНН.
2. Адаптеры сайтов и извлечение через LLM в строгую JSON-схему: факт, URL, цитата, дата, статус проверки. Неподтверждённые поля остаются `null`; инструкции из сайтов не исполняются.
3. Проверка соответствия категории и реальной доставки в регион. Подтверждение человеком перед попаданием в основной каталог.
4. Серверная БД, пользователи, общие заметки, история изменений, плановое обновление, контроль стоимости, ограничение запросов и наблюдаемость.
5. Нормализация товарных позиций и сбор коммерческих предложений для корректного сравнения цен, логистики и полной стоимости закупки.

## Развёртывание

`npm run build` создаёт `dist/server/index.js` и манифест Sites для основного хостинга. На GitHub Pages публикуется `main:/docs`. Секретов в репозитории нет; `.env` исключён из Git. Прямой вызов API разрешён только для ID компаний из каталога, произвольный URL передать нельзя.
